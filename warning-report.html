四、Go 对照根因分析

通过对 tyme4go 原项目逐文件对照分析，这些"死代码"警告的根因可以归结为一个核心差异：Go 的 struct embedding（隐式方法提升） vs. MoonBit 的 composition + extend（显式方法提升）。

Go vs. MoonBit 模式对比

特性 Go MoonBit
继承机制 Struct embedding (type A struct { B }) 组合 (pub struct A { b : B }) + extend A with Trait::{method}
方法提升 隐式、免费、无警告 显式 extend，LSP 警告未使用
fmt.Stringer 隐式 String() 调用 显式 impl Show with to_string
测试可见性 同包测试可见一切 _wbtest.mbt 是独立编译目标
未使用检测 不警告 LSP 报告 unused_value

三类"死代码"的 Go 根源

1. extend 未使用方法（96 个）— Go embedding 的隐式提升

在 Go 中，Animal 嵌入 LoopTyme，自动获得 GetName()、String()、Next() 方法。Go 编译器从不警告未使用的提升方法。

// Go: 嵌入 → 自动方法提升
type Animal struct { LoopTyme }
// animal.GetName()  → 从 LoopTyme 提升
// animal.String()   → 从 LoopTyme 提升

在 MoonBit 中，extend Animal with Culture::{get_name} 是显式方法提升桥。这些方法确实在 _wbtest.mbt 中被调用，但 moon check 不分析测试编译单元。

2. trait 实现未使用（23 个）— Go fmt.Stringer 的隐式调用

在 Go 中，fmt.Sprintf("%v", obj) 通过反射隐式调用 String() 方法。MoonBit 没有隐式 Show 调用机制，必须显式调用。

// Go: fmt 隐式调用 String()
fmt.Sprintf("%v", eventType)   // → eventType.String()
fmt.Printf("%s", ev)           // → ev.String()

3. struct 从未构造（6 个）— Go embedding 的隐式构造

在 Go 中，China95ChildLimitProvider{} 会自动初始化内嵌的 AbstractChildLimitProvider。MoonBit 中这些 struct 变为命名空间（静态方法），无需构造。

// Go: 嵌入 → 隐式构造
type AbstractCulture struct { Culture }    // 嵌入 interface
type AbstractTyme struct { AbstractCulture; Tyme }  // 双重嵌入
type China95ChildLimitProvider struct { AbstractChildLimitProvider }
// China95ChildLimitProvider{} → 自动初始化嵌入链

#warnings 属性抑制方案

对于选择性修复的警告，MoonBit 提供了 #warnings 属性来按声明粒度抑制：

#warnings("-struct_never_constructed")
priv struct AbstractCulture {
}

也可通过 moon check --deny-warn 在 CI 中将特定警告提升为错误。
