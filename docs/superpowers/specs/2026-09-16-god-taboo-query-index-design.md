# God/Taboo 查询索引优化设计

## 背景

`God::get_day_gods`、`Taboo::get_day_recommends`、`Taboo::get_day_avoids`、`Taboo::get_hour_recommends` 和 `Taboo::get_hour_avoids` 都从包内固定编码数据中查询结果。

当前实现保留了上游 Go 版本的数据表达方式，但在 MoonBit 运行时重复完成以下工作：

- `day_gods()`、`day_taboo()` 和 `hour_taboo()` 每次调用都构造数组；
- `God::get_day_gods` 逐字符扫描整段月份数据，创建多个临时字符串并解析十六进制编号；
- `get_taboos` 每次执行两层 `split`，再创建切片并解析十六进制编号；
- 每次调用的目标只是一项固定的“月支或时支 × 日干支”结果，重复扫描和拆分没有业务必要。

现有 `xref_gt_wbtest.mbt` 覆盖全部 `60 × 60` 月、日干支组合及日/时宜忌，为结果顺序和内容提供完整差分护栏。

## 目标

在不改变公开接口、调用方式、返回顺序、错误类型和结果内容的前提下，将 God/Taboo 的运行时查询改为直接索引，并减少重复字符串解析和临时分配。

验收要求：

- `tyme/core/pkg.generated.mbti` 和 `tyme/pkg.generated.mbti` 字节不变；
- 五个公开查询函数的签名与调用方式不变；
- 全部 `60 × 60` 组合的 God/Taboo 结果与优化前完全一致；
- 返回的 `Array[God]` 和 `Array[Taboo]` 仍是每次调用独立创建的数组，调用方修改返回数组不能影响后续查询；
- `moon check --target all` 通过；
- `wasm`、`wasm-gc`、`js`、`native` 四个目标各自通过全部测试；
- native benchmark 显示查询路径得到实质改善，但不设置机器相关的固定耗时阈值。

## 方案比较

### 方案一：只把编码数组提升为模块级私有值

避免每次构造最外层数组，但查询仍然逐字符扫描或执行两层 `split`。

优点是改动最小；缺点是保留主要运行时开销，收益有限。

### 方案二：模块初始化时预解析为嵌套数组

把每个查询单元解析为 `Array[Int]`，运行时按维度直接定位，再把编号映射为新的 `God`/`Taboo` 数组。

优点是实现直观，查询成本与结果数量成正比；缺点是嵌套数组本身有一定对象开销。

### 方案三：压平编号数据并维护偏移索引

把全部编号放入单个扁平数组，每个查询单元保存起止偏移。

优点是内存布局紧凑；缺点是解析器和索引代码更复杂，当前数据规模下收益不足以抵消审查成本。

## 选定方案

采用方案二。

数据只在模块初始化时解析一次。查询函数先根据现有业务规则计算主索引和子索引，再取得已经解析好的编号数组。返回阶段仍逐项调用 `God::from_index` 或 `Taboo::from_index` 创建结果，因此不共享公开返回数组。

此次不修改名称数组缓存。`God::from_index` 和 `Taboo::from_index` 的名称表分配问题作为后续独立优化处理，避免在一个提交中混合两个根因。

## 数据结构

### God

构建私有索引：

```text
月支索引 0..11
  └── 日干支索引 0..59
        └── Array[Int] 神煞编号，保持编码中的原始顺序
```

God 原始数据以分号开头，每条记录由两位十六进制日干支编号和后续两位十六进制神煞编号组成。初始化解析必须保留现有正则等价行为：按从左到右顺序读取匹配记录，并保持记录内编号顺序。

### Taboo

构建两个私有索引，分别对应日宜忌与时辰宜忌：

```text
月支或时支索引 0..11
  └── 日干支索引 0..59
        ├── Array[Int] 宜
        └── Array[Int] 忌
```

初始化解析沿用现有分号、逗号字段规则。空字段解析为空编号数组。

## 错误处理

公开函数继续返回 `Result[Array[God], String]` 或 `Result[Array[Taboo], String]`。

编码数据是包内固定常量，当前全部数据均合法。初始化解析器仍使用可失败的十六进制解析，并将每个单元保存为 `Result[Array[Int], String]`，使潜在的编码错误可以通过原有公开 `Result` 路径返回，而不是在模块初始化时触发不可恢复的 panic。

查询阶段遇到已保存的 `Err` 时原样返回错误文本；遇到 `Ok` 时创建新的领域对象数组。

## 测试设计

### 特征测试

新增白盒测试，覆盖：

- God、日宜、日忌、时宜、时忌的代表性非空结果；
- 编码中的空宜或空忌结果；
- 同一输入连续查询两次，修改第一次返回数组后，第二次结果保持不变；
- 索引的 0 和 59 边界。

测试先针对尚不存在的预解析索引辅助函数编写并确认失败，再实现生产代码。

### 全组合差分

保留并运行现有 `xref_gt_wbtest.mbt`。优化前后分别捕获 native 输出并做字节比较，覆盖全部 `60 × 60` 组合以及名称、顺序和空结果。

### 性能基线

新增 `god_taboo_bench_wbtest.mbt`，在固定输入集合上重复调用五个公开查询函数，并消费返回结果长度，避免只测未使用表达式。

性能记录采用同一机器、同一目标、同一 benchmark 的优化前后对比，不在测试中写入绝对耗时断言。

## 实施边界

本次只修改：

- `tyme/core/god.mbt`
- `tyme/core/taboo.mbt`
- God/Taboo 相关白盒测试
- God/Taboo benchmark

本次不处理：

- `God::from_index`、`Taboo::from_index` 的名称数组共享；
- 其他 `LoopTyme` 类型的名称缓存；
- `equals` 的结构化比较；
- 八字神煞 V2 上下文优化；
- 藏历累计日索引；
- 包拆分或公开 API 调整。

## 风险与控制

- **解析语义偏差**：用优化前后的完整 `xref_gt` 输出做字节比较。
- **结果数组意外共享**：增加返回数组独立性测试，查询时始终新建领域对象数组。
- **跨后端初始化差异**：四个目标分别运行全部测试，避免并行巨量输出造成 UTF-8 流交错。
- **初始化成本增加**：仅执行一次；benchmark 同时记录查询批量执行，以确认常用路径收益覆盖初始化成本。
- **接口漂移**：修改前后保存并比较两个公开 `.mbti` 文件。
